风吟下一版本修改事项（2026-10-09）

状态：用户已确认开始实现下一版 1.1.7。五项范围已进入实现及构建验证；Windows 真机验收尚未完成。

一、安装依赖策略：按用户要求强制执行随包指定版本安装
1. 面向中老年用户，优先保证安装风吟后可使用，且电脑声音链路正常。
2. 对随包提供的 ASIO4ALL、VB-CABLE、Fresh Air 安装程序，每次安装或升级风吟都执行，不因已检测到文件、注册项或相同版本而跳过。
3. 使用随包指定、经过验证的版本；不得沿用当前“存在即跳过”的逻辑。
4. 用户说明当前随包安装程序不需要登录或授权。实施时确认各安装程序的覆盖/修复行为与退出结果，不把启动了安装程序当作安装成功。
5. 不自动扩展至未随包提供的 SWAM、其他商业插件或无关硬件驱动；如需扩展另列范围。
6. VB-CABLE 等安装器如不能直接覆盖，须按其实际支持的方式实现重装及重启衔接，不能误执行卸载后结束并报告成功。

二、明确重启提示（必须落实）
1. 用户反馈现有版本没有明确出现重启提示；下一版本必须在正常安装完成页面明确显示“安装完成，请重启电脑后再使用风吟”。
2. 提供“立即重启”和“稍后重启”的清晰选项；立即重启须由用户选择，提醒保存其他工作。
3. 未重启前不要自动启动风吟，也不要显示可直接开始演奏的误导性提示。
4. 覆盖安装、同版本重装、升级安装均纳入提示检查，不能只依赖“首次安装驱动”分支设置重启标记。

三、安装后的插件发现与验证
1. 依赖安装完成、重启后，风吟刷新实际使用账户的插件扫描缓存，确保新安装的 Fresh Air 进入可用列表。
2. 不把 Windows 应用列表或 VST3 文件存在等同于插件可加载；检查扫描结果及实例创建结果。
3. 已收到的内测 plugins.xml 中无 Fresh Air 记录；该案例应作为安装后自动发现的回归场景。
4. 分清安装失败、未扫描到、版本不匹配、实际加载失败，避免继续统一报“缺失或版本不一致”。

四、验收清单
1. 干净环境：安装全部随包依赖，完成页面有明确重启提示。
2. 已安装相同版本依赖：仍执行指定安装程序，并正常完成；重启提示仍出现。
3. 已安装不同版本或依赖异常：验证最终实际安装结果，不静默跳过、不假报成功。
4. 稍后重启：安装结束不自动打开风吟；立即重启：经用户选择后执行。
5. 重启后：Fresh Air 可被扫描，“次中萨-气包音”可加载。
6. 电脑扬声器、耳机及风吟实际发声；耳机插拔、ASIO4ALL 面板关闭恢复、伴奏桥接正常。
7. 安装失败或取消时明确提示未完成组件，不能显示全部就绪。

五、明确暂缓：通用板载声卡适配
1. 用户确认：声卡适配先不做。下一版本不增加其他厂商板载声卡或通用驱动的自动端点识别分支。
2. 保留当前音频端点选择及启动恢复逻辑，不借安装依赖修改扩大音频路由改动范围。
3. 此暂缓不取消前述随包依赖强制安装、重启提示、插件发现与验证事项。
4. 本次仅更新清单；继续保持不编译、不发布。

六、登录后轻量声音恢复（用户确认纳入下一版）
1. 用户登录、音频设备就绪后执行轻量恢复程序，不打开主界面，不常驻完整 ASIO 音频引擎；检查/恢复完成后退出。
2. 仅处理有风吟路由所有权/恢复记录支持的残留默认输出：风吟未运行、当前角色仍指向风吟记录的虚拟输出时，恢复该角色此前的可用物理输出。
3. 默认输出已经是正常物理设备时不修改；没有可靠所有权记录时，不凭名称为 VB-CABLE 就强行切换，避免覆盖用户自行设置的直播/录音路由。
4. 安装前记录默认输出，依赖安装及重启后完成恢复衔接。用户实测确认：风吟运行时直接重启，重启后默认输出残留 VB-CABLE；先关闭风吟再重启，则为正常扬声器。该对照定位了风吟运行中重启的残留场景；具体是恢复未执行、未完成，还是系统音频服务退出时序导致失败，仍需代码与日志核查。
5. 恢复程序与风吟启动/退出必须协调，避免登录恢复与主程序同时切换设备；按 Windows 音频角色分别检查当前状态后恢复，保留用户期间主动修改的选择。
6. 设备就绪等待与失败重试应有上限；无可用物理输出或恢复失败时保留诊断，不循环切换，不启用虚拟线缆作为物理输出替代。
7. 现有演奏链路不因恢复程序启动而被重建；不扩展通用声卡适配。风吟桥接应在链路就绪后接管默认输出，并在退出/异常时恢复，相关顺序调整需单独回归。
8. 验收覆盖：正常物理默认输出保持不变；安装后重启且不开风吟可播放网页；直接关机/异常退出残留恢复；手动选择虚拟输出不被误改；与风吟同时启动；耳机插拔；无设备/延迟就绪；多次登录无反复切换。
9. 风险说明：新增恢复路径及依赖重装均存在回归风险，不能保证正常电脑绝不受影响。先在已正常机器上验证上述场景，再发布；当前仅确认需求，未实现或验收。

七、风吟运行中关机/重启的输出残留（用户确认纳入）
1. 在系统关机/注销阶段提前尝试恢复物理输出，不只依赖普通退出清理；不能因尚可取消的关机通知而永久破坏继续运行的音频状态，需覆盖取消关机后的恢复。
2. 下次登录通过第六节轻量恢复程序处理上次未完成的恢复，成功后清理记录；失败保留记录和诊断，不假报成功。
3. 不改动目前正常的演奏、耳机切换及普通退出恢复行为；系统退出处理与现有恢复逻辑共用安全协调机制，避免重复操作或竞争。
4. 核心验收：开着风吟直接重启，重启后不开风吟，网页经真实扬声器/耳机正常出声，默认输出不残留风吟接管的 VB-CABLE。
5. 对照验收：先关闭风吟再重启仍正常；运行中关机后再开机、注销再登录及取消关机均不遗留错误路由；正常物理默认输出和用户主动设置不被误改。

八、SWAM 起音适配（2026-10-09 用户实测确认并授权修改）
1. 用户实测将 Attack Control 改为 Expression 可解决雅马哈大音头；当前 SWAM 方案统一改为 Expression。
2. 已修改随包两套音色、内置高萨参数，并增加加载/切换后的运行时统一设置，按参数名和显示值匹配，不猜测跨乐器索引；不存在对应选项时不写入并记录日志。
3. 不改音量、表情曲线、ASIO 或非 SWAM 音源；新安装包尚未编译，Windows 真机回归尚未完成。
4. 后续用户提供新包：检查 Attack Control；未设 Expression 时提醒用户确认修改，不静默改写原包。规则存于根目录 AGENTS.md。
5. 验收：各 SWAM 音色加载/切换后实际显示 Expression；雅马哈轻吐/重吐/连奏/收尾；其他电吹管不出现异常；保存重载一致；民乐/效果器不受影响。

九、本次实现与验证进度
1. 安装依赖：每次执行三个随包安装器并检查退出结果及存在性；VB-CABLE 移除后须重新安装，不完成则中止，不假报完成。原厂需要重启的重装流程不能跳过。
2. 安装结束强制进入重启提示流程，无自动启动主程序；不擅自替用户选择立即重启。
3. 安装代次标记触发当前账户插件重扫，Fresh Air 在隔离扫描子进程中验证实例创建；失败保留诊断，扫描失败不标记代次完成。
4. 新路由记录保存接管的虚拟端点，原子写入；恢复仅修改仍在接管端点的音频角色。安装前以原始登录用户保存物理输出；用户此前选择的虚拟输出不接管。

7. 不纳入随机滑音、未定位的卡死、非 Realtek 声卡适配、音量双映射或无条件放宽插件身份校验。
