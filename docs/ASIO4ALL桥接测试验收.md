# ASIO4ALL 桥接测试

本版物理输出仅使用 ASIO4ALL。系统声音通过风吟虚拟扬声器的 loopback 输入进入同一个混音引擎。不再使用 WASAPI 独占作为物理输出，也不静默提高到 512 帧。

## 已安装测试驱动的电脑

无需重装已正常工作的风吟虚拟声卡、无需再次改变测试模式。

1. 退出旧风吟，使用新包中的 FengYin.exe（不要混用旧引擎文件）。
2. 声音设置点击“配置 ASIO4ALL”。配置期间风吟暂停音频。
3. ASIO4ALL 中仅启用实际使用的 Realtek 扬声器或耳机输出。关闭麦克风等输入，尤其不要启用“风吟共享扬声器”作为 ASIO 硬件输出，防止回路。先设 128 帧。
4. 关闭控制面板，选择“风吟低延迟（ASIO4ALL）”。应用实际缓冲区以驱动返回值为准。
5. 在较低的音量下同时播放网页和吹奏。只有声音正常后再适度调大；若出现强噪音立即停止。
6. 测试 128、256；检查 UI 显示的实际值，不能只看申请值。不要用 512 的启动成功代替低延迟验收。

## 必须实机通过的项目

- 日志 Backend=ASIO4ALL；显示实际驱动名、实际缓冲区、输出通道。
- 128 或 256 稳定吹奏，网页同时发声，两路不出现异常衰减、噪音或持续断供。
- 连续运行 15 分钟，切换音色、播放/暂停网页、重复启动退出三次。
- 退出或引擎失败后恢复物理系统输出；ASIO4ALL 释放设备。
- 缓冲区修改失败时明确报错，不悄悄换 WASAPI，不把估算延迟称为实测。
- ASIO4ALL 的耳机/扬声器路由由其控制面板管理；本版不宣称自动跟随所有硬件插拔。

## 诊断

`%APPDATA%\FengYin\audio-engine.log` 记录驱动启动错误、申请和实际缓冲区、驱动报告延迟、五秒一次的回调/断供/削波计数。计数用于定位，不代表已测得 MIDI 到扬声器的端到端延迟。

Windows CI 不具有用户的 Realtek 和 ASIO4ALL 硬件链路，不能替代上述实机验收。
# 音频链路诊断版操作

已安装且状态正常的虚拟驱动不必重装。关闭旧风吟，解压整个新包，在新目录运行 FengYin.exe，不单独混用旧 EXE。

1. 调低耳机/音箱音量，关闭浏览器，选择“风吟低延迟（ASIO4ALL）”。
2. 声音设置→“测试输出（2秒）”，确认后记录是否听到声音。测试音为440 Hz、-30 dBFS，并暂时替代混音。
3. 加载乐器，吹奏10秒，记录是否有声。
4. 打开浏览器播放网页声音10秒，记录是否有声，然后点“导出诊断”，发送桌面的诊断TXT及以上三个结果。
5. 如果模式启动失败或提示没有实际输出，停止反复切换，直接导出诊断。

诊断包含音源输出峰值、客户端发送峰值、引擎接收峰值、混音输出峰值、ASIO初始化日志和Windows音频会话的进程名/PID/设备名。不会收集音频内容、网页地址、许可证私钥。峰值按5秒窗口统计；零值不等于故障，必须结合测试时段。ASIO前非零不代表物理声卡已经发声。
