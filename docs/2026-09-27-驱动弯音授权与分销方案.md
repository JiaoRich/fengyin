# 驱动、弯音、授权与分销：检查结果与实施边界

日期：2026-09-27。本文区分已修改、待实机验证与待确认方案，不代表全部功能已发布。

本轮验证：本机 FengYin 编译通过（存在既有 ToneStyleCatalog 初始化警告）；67 项 Python 回归检查通过；11 项 CTest 通过，含硬件码授权及旧码兼容测试。Python 中的源码断言只防代码回退，不证明 Windows 脚本实际效果。未发布新版安装包；未在当前 macOS 执行 Windows 驱动更换。

## 1. 驱动优化

确认的问题：MainComponent 用 lastNote >= 0 阻止驱动操作，但 MIDI Note Off 没有清除该字段；停吹后仍可能一直被当成演奏中。PowerShell 仅因存在 Dolby/Nahimic 服务就退出，没有验证其是否真的阻碍切换。

本次修改：

- Note Off 后从实际仍按下的音符刷新 lastNote，无音符则归零为 -1。
- 用户确认后自动暂停本软件伴奏、结束并保存录音、收音，取消正在进行的缓冲测试；脚本运行期间不继续向音源发送吹奏。
- 去掉 Dolby/Nahimic 服务存在即退出的判断，不卸载、不永久停用用户的其他软件。
- 接受 pnputil 的 3010（需要重启）结果，不把它当作普通失败。
- 每次导出使用独立备份目录，不再删除上一次的驱动备份。
- 恢复后核对实际绑定的驱动提供者和版本；未确认绑定时不显示“恢复成功”。

仍保留权限、唯一目标设备、驱动包存在、成功备份的校验。这些不是播放状态误判；无法备份或无法识别目标时继续卸载会破坏回滚能力。

这是切换 Windows 内置 hdaudio 通用驱动，不是下载“微软最新声卡驱动”，也不保证降低每台电脑的延迟。

待 Windows 验收：空闲运行、吹过后停吹、正在录音时保存文件、播放中自动暂停、存在 Dolby 服务、取消 UAC、驱动导出失败、重启返回码、重复运行、恢复原驱动及重启。macOS 编译不能验证这些系统行为。

## 2. 其他软件耳机无声

不能仅凭症状认定是默认设备问题。需要分成两类：

1. Windows 声音设置能看到耳机，系统测试音能响：核对系统默认输出、默认通信输出、相关应用自己的输出选择。换驱动可能改变端点身份；应用可能仍记住旧端点。
2. 耳机端点消失，或系统测试音也不响：怀疑通用驱动与厂商插孔路由/检测不兼容，优先恢复 OEM 驱动验证。宿主软件不能弥补缺失的底层插孔实现。

不自动清空其他应用的输出偏好，不把所有声音强制送到任意一个设备。保留“跟随系统默认输出”；恢复 OEM 驱动后继续使用共享低延迟接口进行缓冲测试。

验收必须包括系统测试音、浏览器/播放器、风吟，插拔耳机与重启，不能只验风吟本身。

参考：[Microsoft 默认音频端点选择](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/default-audio-endpoint-selection)、[UAA 驱动](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/uaa-class-drivers)。上述两类是排查假设，不是已确认的用户电脑根因。

## 3. 弯音范围方案（待确认，未改参数）

“西洋 ±1、民乐 ±3”可作为部分乐器的产品默认建议，不能作为普遍演奏标准。音高连续变化能力与乐器模型、奏法相关，不能把小提琴、钢琴、长笛、二胡、编钟统一处理。

现有链路：MidiInputService 接收 Pitch Bend，经归一化后 PluginHostEngine 还原为 14 位 Pitch Wheel。半音范围主要由插件决定，不是风吟统一乘以 ±2。普通音色风格的参数保护列表排除了弯音范围。

另发现空音 KAM 转换硬编码 RackParam（包括 PitchbendUp=10.0、PitchbendDown=2.0）；没有证据证明这两个内部值就是半音。不得直接拿 KAM 数字与插件 state 数字互换，也不能将其当成已实现用户范围。

建议配置：

| 范围 | 建议 |
| --- | --- |
| SWAM 萨克斯及经验证适用的管乐 | 新默认方案建议 ±1 半音，需试听；不覆盖用户保存值 |
| 西洋弦乐、特殊管乐模型 | 跟随原厂；用户按奏法选择更大范围 |
| 二胡等需要滑音的民乐 | 可建议 ±3，先确认空音对应参数的单位与实际行为 |
| 打击、键盘、复合采样方案 | 跟随原厂，不按“民乐”标签统一改写 |

界面放在智能适配的高级选项，仅一行“弯音范围”：跟随音源 / ±1 / ±2 / ±3 / 自定义。自定义允许分别设置向上、向下范围，范围上限以插件实际能力为准。音源不支持可靠读取/写入时只提供“在原厂界面调整”，不能显示一个不起作用的下拉框。

按音源乐器保存用户覆盖值，切音色风格、重连吹管不重置；用户方案自己的设置优先。保持 MIDI 中心与完整幅度，不通过宿主额外放大再叠加插件范围。切换范围时先回中，避免遗留跑调。

验收：中心不偏移；满幅上下实测半音数；不对称范围；切风格、换乐器、重启持久化；用户原厂修改回读；不影响移调、气息、技巧映射。

参考：[SWAM 木管手册](https://static.audiomodeling.com/manuals/woodwinds/SWAM%20Solo%20Woodwinds%20v2.9.2%20-%20User%20Manual.pdf)、[Audio Modeling 物理建模长笛弯音说明](https://kb.audiomodeling.com/support/solutions/articles/206000050963-how-does-pitch-bend-work-in-a-physically-modeled-flute-)。后者说明特定模型的限制，不代表所有 SWAM 版本行为相同。

## 4. 激活绑定

旧机器码使用 uniqueId + fileSystemId，系统分区重建可能改变后者。本次改为 JUCE 固件硬件标识，不再加入分区序列号或电脑名；读不到硬件标识则明确报错，不给多台机器生成同一个空标识机器码。

兼容：原系统上的旧签名激活码继续验证。旧码不会自动变成新硬件码；已重装且旧机器码变化的用户需要一次换发。主板更换、部分固件信息变化也可能需要换绑，不能承诺所有硬件变动都保持同一个码。

重要区别：硬件绑定稳定，不等于授权文件永不丢失。重装清除 license.dat 后，需要重新输入同一个新激活码，或通过未来的订单找回自动重新下载授权。离线软件不能凭空恢复已删除的购买凭证。

建议后续授权服务：订单绑定设备硬件码；重装后验证订单身份，匹配原设备后自动发回同一授权，不重复收费。换电脑采用明确的换绑次数与人工异常处理政策。私钥只在服务端或现有离线签发工具，不进客户端。

验收：同机重启/重装码稳定；新码重新输入有效；旧版原系统升级仍可用；复制授权到其他硬件无效；硬件 ID 不可读有提示；试用到期不因升级重置；找回授权必须验证订单所有权。

## 5. 软件内付费、激活、分销（规划，未开发）

用户链路：点击购买 → 展示价格和授权范围 → 微信扫码 → 服务端确认实付 → 自动签发并保存设备授权 → 立即可用。付款/找回联网，已激活后演奏离线；支付服务不可用不影响已有离线授权。

后台组成：订单与支付、设备授权、推广渠道、佣金台账、每日对账、售后退款。先一个商户统一收款，合作博主只做一级渠道推广，不做复杂多级分销。

渠道归属：每个博主有专属链接/二维码/邀请码。下载页面到软件通过签名渠道凭据传递；复制安装包丢失来源时允许输入邀请码。付款前展示归属，订单创建时固定 channelId、佣金比例及规则版本，支付后不允许客户随意改归属。比例变化只作用于新订单。

订单记录：订单号、支付平台流水号、产品、标价、优惠、实付、退款、支付手续费、渠道、比例快照、授权状态、佣金状态、结算批次；金额全用整数分。

建议佣金基数：用户实付减退款（是否再减支付手续费需在合作约定中固定）。例如实付199元、比例30%、无退款，佣金59.70元；不是按软件标价计算。报表分别显示实收、退款、手续费、应付佣金、已付佣金、商户净额，不能用一个“到账”字段混在一起。

每日自动核对：支付平台交易/退款/资金账单 ↔ 内部订单 ↔ 授权 ↔ 佣金。签名验证、服务端查单、金额核验、回调幂等是必须项；重复通知不重复激活或返佣。付款后断网通过查单补发；只看到客户端“成功”不能发授权。

结算：经过约定退款观察期后进入可结算金额。可先自动算账、生成结算批次，由店主确认付款；开通官方分账后可自动执行，但需要商户权限、接收方信息与平台比例限制。佣金比例可逐渠道不同，实际付款不能越过平台允许范围。分账失败保留待处理状态，退款按原订单规则冲减未付佣金或记负账，不假定已付给个人的钱能无条件扣回。

上线前需要用户提供/确认：商户主体和微信商户号、域名与服务部署、售价/优惠政策、设备数/换绑政策、渠道归属规则、佣金基数/比例、退款与结算周期。未确认前不接真实收款。

验收：成功付款自动激活；重复回调；金额异常；支付中断网重试；旧订单找回；伪造渠道参数；比例变更；部分/全额退款；分账失败重试；对账差异报警；权限隔离（博主只看自己渠道）；备份恢复与私钥隔离。

## 6. 空音无声继续排查

仍未证明已解决。当前转换函数并非原封不动保存原厂状态，而是将部分字段重新组装为 KAM，再转换为另一个 State；单个参考文件匹配不能证明所有参数/运行时初始化完整。

下一验证必须比较：原厂手动载入 KAM 的状态与输出、宿主恢复原始组件状态的状态与输出、宿主转换 KAM 的状态与输出。同时记录采样加载完成时机、MIDI通道、输出总线、CC与Note事件，隔离恢复与后续 resetPerformance 的影响。不得再根据 IsSelected 等单个字段猜测根因并宣称修复。

本次不再增加未经实机证明的 KAM 参数替换。验收至少覆盖创建后立即吹奏、切走再切回、退出重开、二胡与笛子、原厂界面不打开也发声。当前机器的本机编译/自动测试不能代替 Windows 空音 3.11 发声验证。
