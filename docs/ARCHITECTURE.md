# 技术架构草案

## 目标

将界面、实时音频和第三方插件隔离，确保动画或视频卡顿不会影响演奏声音。

## 分层

1. **界面层**：中文界面、视频播放器、动态电平和设置。
2. **应用层**：音色方案、设备配置、激活状态、持久化。
3. **实时引擎**：MIDI 输入、映射、音频图、录音和性能监控。
4. **插件层**：VST3 扫描、验证、加载、状态保存和故障名单。
5. **平台层**：Windows MIDI、ASIO、WASAPI、文件系统和机器标识。

## 推荐正式技术路线

- C++20 + JUCE 9.0.2（发布前确认商业许可）
- CMake + Visual Studio 2022
- VST3 SDK（仅支持 64 位 VST3）
- Windows MIDI API，后续评估 Windows MIDI Services
- ASIO + WASAPI
- SQLite 或轻量 JSON 持久化
- 独立插件扫描进程

## 线程原则

- 音频线程禁止磁盘、网络、锁等待和界面操作。
- MIDI 消息在进入音频图前完成轻量映射。
- 频谱数据通过无锁环形缓冲传递给界面。
- 视频解码与音频插件处理互不阻塞。
- 界面过载时降低动画帧率，音频优先级不变。

## 里程碑

1. 交互原型与视觉基线。
2. Windows 空壳程序、设置持久化和激活流程。
3. MIDI 设备检测、气息映射和模拟音源验证。
4. ASIO/WASAPI 音频输出与内置效果。
5. VST3 扫描、SWAM 加载和状态保存。
6. 视频混音、录音、诊断和稳定性测试。

## 当前实现状态

- 已建立 C++/JUCE 应用入口和主界面。
- 已建立 MIDI 输入服务，支持音符、力度、CC 气息和 Pitch Bend。
- 已建立可脱离 JUCE 测试的气息曲线和平滑核心。
- 已建立音频设备服务，支持设备类型、输出设备、采样率和缓冲区配置。
- 已建立实时测试音源，使用无锁单生产者/单消费者队列接收 MIDI、气息和弯音。
- 已建立 VST3 目录与后台扫描服务，包含扫描进度、缓存、失败列表和“死亡踏板”恢复文件。
- 已建立 VST3 实例播放器，支持异步加载、实时 MIDI、CC2/CC11 气息、Pitch Bend 和插件状态序列化。
- 已建立 SWAM 分类器，可识别萨克斯、铜管、木管、弦乐及其他 SWAM 产品。
- 已建立音色方案仓库，使用 XML 版本标记、插件唯一标识、Base64 插件状态和原子文件替换。
- 已将扫描、选择、加载、保存方案和恢复方案接入原生中文界面。
- 已建立原生视频面板，支持异步选择、播放、暂停、停止、进度定位、时间和音量。
- 已建立完全离线的永久授权：稳定本机码、RSA 数字签名验证、原子保存和启动复验。安装包只含公钥，私钥不进入应用。
- 已建立 24-bit WAV 演奏录音器，通过后台 FIFO 写盘，同时覆盖测试音源和 VST3/SWAM 输出。
- 已建立简化音频设备面板，覆盖驱动、输出、采样率和缓冲区，并使用应用属性文件持久化 JUCE 设备状态。
- 已建立电吹管连接向导和 6 秒长音气息识别，并按 MIDI 设备分别持久化首选设备与气息 CC。
- 已建立三档式吹奏手感面板，覆盖气息曲线、平滑、起音门槛和弯音缩放；映射器更新使用短时自旋锁与 MIDI 输入线程同步。
- 已将单插件播放器升级为 AudioProcessorGraph 串联链，支持一个乐器节点、一个可选效果节点、MIDI 输入和立体声输出。
- 音色方案升级为版本 2，分别保存音源与效果器的唯一标识和二进制状态，同时向后兼容版本 1。
- 音色仓库已支持收藏、删除和独立默认方案指针；收藏方案在界面置顶，默认方案在授权有效且插件缓存就绪后自动恢复。
- 最终输出服务现统一处理总增益、左右峰值与频谱采样；音频线程只写无锁 FIFO，界面线程执行 2048 点 FFT 和 54 个对数频段映射。
- 首次启动向导按授权、MIDI、音频、插件缓存的实时状态逐项引导，完成标记保存在用户应用数据目录。
- 录音管理读取 WAV 元数据展示时长和大小，删除请求使用操作系统回收站而非永久删除。
- 已支持原生/通用插件编辑器窗口、效果节点旁通、总输出增益和最终混音双声道峰值采集。

## 视频音频路线

当前播放器优先验证本地 MP4 的兼容性和界面流程，使用操作系统原生视频后端。后续录制阶段需要把视频伴奏声音送入统一音频混音器，才能与 SWAM 一起录制，并确保选择 ASIO 时使用同一输出设备。

当前录音已在最终音源输出回调处取样，所以 VST3/SWAM 演奏声能够可靠写入 WAV。伴奏音轨服务使用独立预读线程、采样率转换和音量控制，把可解码音轨混入同一个最终回调，再一起送往声卡与录音器。播放、暂停、停止、拖动和超过 250ms 的漂移都会与视频时钟同步。

在 Windows 上，系统视频后端与音频格式读取器支持的容器不完全相同。统一伴奏通道现采用三级降级：直接解码视频音轨、自动匹配同名音频、后台提取到应用缓存。缓存键包含视频路径、文件大小和修改时间，视频更新后自动重新提取。提取输出为 48kHz/24-bit/双声道 WAV，并以临时文件完成后再移动，避免中断时留下半成品。当前开发环境尚未放入提取器可执行文件，正式分发前需完成 FFmpeg 许可审查和 Windows 打包。

## 永久激活路线

用户把软件显示的本机码发给安装人员，安装人员使用不随安装包发布的内部工具生成唯一激活码。软件离线验证签名并保存在当前用户的应用数据目录，之后每次启动自动复验。重装系统或更换主要硬件可能产生新本机码，届时由安装人员人工换发，不需要部署授权服务器。

## 插件扫描安全演进

当前扫描服务已在后台线程运行，并用 JUCE 的死亡踏板文件记录扫描中的插件。正式发布前将把扫描器移动到独立进程；这样即使第三方插件本身崩溃，也不会带走主演奏程序。
