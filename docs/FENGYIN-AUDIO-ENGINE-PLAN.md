# 风吟音频引擎 1.1.0：完整开发与验收方案

## 产品目标

用户只安装一个风吟安装包并确认一次管理员权限。首次启动由软件自动准备声音环境；以后插入电吹管即可演奏。风吟、网页、微信和播放器可以同时从当前扬声器或耳机发声，演奏链路目标延迟 6–12 ms。任何异常都必须自动恢复 Windows 原有声音，不允许造成无法启动、无法关机或必须断电重启。

这不是在现有声音设置里再增加一个第三方驱动选项，而是一套独立的音频子系统：

```
风吟 MIDI → SWAM/效果链 → 快速共享内存 ─┐
                                         ├→ 风吟音频引擎 → 物理扬声器/耳机
Windows 应用 → 风吟共享扬声器 → 系统音频环 ─┘
```

物理输出由风吟音频引擎统一管理；普通应用使用固定的“风吟共享扬声器”。虚拟设备是安装时创建的固定端点，不在运行过程中动态创建或删除。

## 支持范围

- Windows 10 22H2、Windows 11 22H2 及以上，x64。
- 固定内部格式：48 kHz、32-bit float、双声道。
- 首批输出后端：WASAPI 独占事件驱动；硬件不支持时自动回退 Windows 共享模式。
- 128、256、512 三档缓冲；自动测试从 256 开始，稳定后尝试 128。
- 不依赖 SAR、KoordASIO、ASIO4ALL，也不修改 Realtek 厂商驱动。
- 蓝牙音响不作为低延迟目标；蓝牙 MIDI 不受影响。

## 组件划分

### 1. 固定虚拟播放设备

- 基于微软 WaveRT/SysVAD 架构实现“风吟共享扬声器”。
- 仅公开实际需要的 48 kHz 双声道格式，减少兼容分支。
- 将 Windows 共享混音送入用户态音频引擎，不模拟硬件、不生成测试音。
- 驱动安装、升级、卸载均使用标准 INF/PnP 流程。
- 正式发布必须使用微软认可的驱动签名；开发测试包使用隔离测试机和测试签名。

### 2. 独立音频引擎进程

- 独立于 FengYin.exe；界面崩溃不会锁死物理声卡。
- 每用户会话启动，不运行在 Session 0，不依赖管理员身份常驻。
- 使用事件驱动 WASAPI 独占流、MMCSS `Pro Audio` 线程和预分配内存。
- 混合风吟快速通道与系统应用通道，统一输出到当前物理设备。
- 监听默认物理输出和耳机插拔，只重启输出流，不重载 VST。
- 心跳、看门狗、崩溃恢复、关机预停止和超时强制释放均由引擎负责。

### 3. 风吟快速通道

- SWAM、空音、技巧映射、气息处理和效果链继续运行在 FengYin.exe。
- 现有实时回调产生的最终乐器/内置伴奏双声道音频写入无锁共享内存环。
- 不在实时线程执行锁、磁盘 I/O、日志、内存分配或进程控制。
- 引擎失联时立即静音快速通道并切回普通共享输出，避免卡死。

### 4. 安装、恢复和诊断

- 安装器一次完成主程序、音频引擎、虚拟设备和自启动项安装。
- 首次启动执行无声稳定性预检，记录每个物理端点的稳定缓冲档位。
- 提供“一键恢复系统声音”，停止引擎、恢复原默认设备并禁用虚拟路由。
- 卸载前必须恢复原默认设备；卸载失败不删除恢复信息。
- 诊断包只包含设备 ID、周期、缓冲、xrun、崩溃阶段和版本，不包含用户音频。

## 用户链路

1. 双击风吟安装包并确认一次 UAC。
2. 首次启动显示“正在准备低延迟声音环境”。
3. 自动检查物理输出、引擎、虚拟设备、128/256 稳定性。
4. 自动成功时显示“声音环境已准备完成”；若 Windows 未允许自动选择默认设备，只要求用户在系统面板中点击一次“风吟共享扬声器”，风吟实时检测并继续。
5. 日常启动直接恢复已验证配置。耳机插拔采用短淡出、切换、淡入，不重新扫描音源。
6. 引擎异常时自动恢复普通共享模式，软件仍可吹奏。

## 现有功能风险与隔离策略

| 功能 | 风险 | 隔离与验收 |
| --- | --- | --- |
| SWAM/空音加载 | 更换回调驱动可能改变插件块大小或生命周期 | VST 仍留在主进程；切换模式前发送 All Notes Off；按 128/256/512 逐一加载、切换、退出 |
| 气息与技巧映射 | MIDI 与音频时钟基准变化可能产生偏移 | 共享单调时钟/QPC；保持现有 MIDI 队列和 sample offset 逻辑；做气息、弯音、技巧回归 |
| 音色方案/第三方效果器 | 设备重启可能重复初始化或丢失状态 | 不重建插件图；只暂停音频泵；对每类预设保存前后状态做字节级核对 |
| 内置视频伴奏 | 与系统通道重复混音或不同步 | 内置伴奏仅走风吟快速通道，不再经过虚拟扬声器；检查更换视频、暂停、定位 |
| 录音 | 系统应用声音在引擎进程中，当前录音仍在风吟进程 | 1.1.0 保持“乐器＋内置伴奏”语义，不录制网页/微信；避免破坏已有录音结果 |
| 耳机/音响插拔 | 输出重启时无声、咔哒或死锁 | 引擎执行淡出/淡入；主程序和插件不重启；连续插拔 30 次验收 |
| 声音设置 | 多个组件保存不同缓冲造成状态分裂 | 只允许引擎拥有最终缓冲配置；UI显示引擎实际值，不显示申请值 |
| CPU/旧电脑 | 多进程、重采样和多缓冲增加负载 | 固定 48 kHz；零拷贝/单次拷贝；旁路不用的通道；压力测试后自动使用 256/512 |
| 启动/关机 | 后台引擎持有设备导致二次启动、重启失败 | 单实例互斥、心跳租约、预关机处理、2 秒释放超时、故障注入测试 |
| 激活与用户数据 | 新进程错误读取或迁移配置 | 音频引擎不接触激活密钥、客户资料或音色方案；只读取独立音频配置 |

## 开发阶段（功能未完成前不向用户显示入口）

### A. 可测试的实时核心

- 固定版本的共享内存协议、无锁音频环、心跳和状态机。
- 离线混音器、欠载静音、过载丢弃、淡入淡出和时钟漂移测试。
- 主程序输出适配层，普通共享输出仍为唯一公开模式。

### B. Windows 音频引擎

- 独立进程、单实例、IPC、WASAPI 独占事件驱动、MMCSS。
- 物理输出枚举、128/256/512 切换、失败原子回滚。
- 耳机插拔、休眠唤醒、关机和崩溃恢复。

### C. 固定虚拟设备

- WaveRT 虚拟播放端点及系统音频传输通道。
- INF 安装、升级、卸载、签名测试和 Windows 音量合成器验证。
- 浏览器、微信、播放器和系统提示音同时播放。

### D. 产品化整合

- 首次自动检测、用户提示、恢复按钮、诊断导出。
- 安装器事务、失败回滚和卸载恢复。
- 全量现有功能回归与多硬件测试。

## 交付门槛

以下项目全部通过后才提供测试安装包：

- 连续启动/退出风吟 50 次，无残留进程、无第二次启动失败。
- Windows 正常重启/关机 20 次，无卡死。
- 浏览器视频与风吟同时发声至少 60 分钟，无持续爆音、无声道丢失。
- 128 不稳定时自动回滚 256；切换失败不退出、不切错驱动。
- 插拔耳机 30 次，声音跟随正确，SWAM 不重载，音符不挂起。
- 休眠/唤醒 20 次，引擎恢复或自动回退共享模式。
- 强制结束 FengYin.exe、音频引擎和 Windows Audio 服务，均能自动恢复。
- SWAM、空音、12 类核心音色、硬件/气息技巧、弯音、移调、视频更换、录音逐项通过。
- 安装失败、升级失败、卸载失败均能恢复原默认输出。
- Windows 10/11、Realtek（含 Dolby/Nahimic）、USB 声卡至少各一套实机通过。

## 外部前置条件

- Windows 11/10 测试机，Visual Studio 2022、WDK 11、WinDbg。
- 隔离的驱动测试环境；开发阶段不在日常工作电脑开启测试签名。
- 正式分发前准备 EV 代码签名证书、Microsoft Partner Center Hardware 账户和驱动签名流程。
