# 1.1.35：应用内连接蓝牙 MIDI 电吹管

## 范围

在现有连接状态区域打开设备管理。全屏使用侧栏/顶部连接状态，精简模式使用标题栏的连接入口；演奏及录制控件保持原位。

- 搜索 Windows BLE MIDI 电吹管；已发现设备可以连接，仅未发现的历史设备置灰。
- Windows MIDI 输入端口打开后才显示“已连接”；不以配对完成或收到首个吹奏音符代替。
- 历史按设备 ID 保存，同名设备不合并。断开保留记录；忘记设备需确认，清除记录并解除系统配对；解除失败保留记录并报告。
- 关闭弹窗停止搜索；已开始的连接继续，仍可重新打开取消。手动断开后不自动重连，意外断连清除气息、持音和技巧，并由用户重新连接。
- 一次只启用一个演奏输入；选择蓝牙不改变 USB 的 WinMM 驱动。蓝牙和 USB 共用 MidiInputService 的气息、音符、弯音和技巧解析。
- 不安装 Windows MIDI Services 预览版本，不实现私有 GATT MIDI 解包，不改变音色方案、增益、采样率、ASIO、录音及录屏链路。

## 实现边界

BluetoothMidiService：发现、GATT 服务核实、配对、Windows MidiInPort 端口、历史及连接状态。控制任务使用独立 MTA 工作线程。Windows 要求可能弹出同意提示的异步 API 在 UI 线程启动，但所有等待、枚举、GATT 查询和端口打开等待均在工作线程进行。MIDI 回调直接进入原有输入处理，不经浏览器、磁盘或 UI 定时器。

搜索主动扫描 20 秒；通过 MIDI 服务 UUID 或 GATT 服务验证排除普通蓝牙设备，避免单凭名称筛选。已配对且仍物理连接的设备即使不广播也会再核实服务。历史设备的配对状态不等同于附近在线。

端口通过 System.Devices.ContainerId 与选中的 BLE 设备精确关联，禁止按名称猜测端口，避免打开同名 USB 或另一台电吹管。Windows 配对同意由操作系统控制；需要确认时仍可能出现系统提示。当前支持常见 ConfirmOnly 配对，要求输入 PIN 的控制器若无法完成将明确提示重试或 USB，不静默声称兼容。

连接请求可取消，陈旧完成结果按请求代数隔离；跨线程 MIDI 回调在断开及析构之前停用。事件回调有独立生命周期守卫。完成连接有独立端口代数，同 ID 重新打开不会复用失效的回调。

## 验证与交付

- 浏览器自动化：发现/历史、重复名称稳定 ID、取消、忘记确认、USB 切换、文本转义、精简触屏布局。
- 原生回归：共享解析器的 CC11、Note On、断连清零、迟到消息丢弃、手动断开禁止自动接管；无效端点不得打开/解除配对，重复退出安全。
- 保留既有完整 Python、C++、精简界面和录制/新手指引检查。
- Windows 独立后端编译和生命周期测试先于完整安装包构建。
- 当前开发机与 CI 没有真实蓝牙电吹管，不能据此声称已实测无线延迟、射频抗干扰、休眠重连或不同硬件的系统配对兼容。交付安装包后需在真实 Windows 电脑和电吹管上确认这些硬件指标；USB 原有路径不依赖蓝牙模块。
